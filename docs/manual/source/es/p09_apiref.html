Capítulo 9Referencia de la API

Todas las rutas empiezan con /api. Las fechas siempre son texto local YYYY-MM-DD. El dinero siempre es un número entero de colones. Para probarlas a mano, corra la API sola y abra http://localhost:5080/swagger.

Formato de los errores

400 — datos con errores (un mensaje en español por campo):

{ "errors": {
    "date": ["La fecha no puede ser futura."],
    "items[0].unitPrice": ["Escriba el precio por cartón."]
} }

409 — rechazado por una regla (mensaje para mostrar tal cual):

{ "message": "María todavía debe ₡8.000.
  Solo se puede borrar un cliente que
  esté al día." }

404 no tiene cuerpo: no hay nada activo con ese id.

Ventas — /api/sales

MétodoRutaQué haceRespuestas
GET/sales?from=&to=Ventas entre dos fechas (incluidas), más nuevas primero, con cashTotal y creditTotal.200, 400
GET/sales/last-pricesÚltimo precio por tipo de cartón: { "A": 2500, "B": 4800 }.200
GET/sales/{id}Una venta con líneas, cliente, paidNow y owed.200, 404
POST/salesCrea una venta (cuerpo: SaleCommand).201, 400
PUT/sales/{id}Edita una venta (mismo cuerpo).200, 400, 404, 409
DELETE/sales/{id}Borra la venta, sus líneas y su abono "pagado al vender".204, 404, 409

Cuerpo de POST/PUT:

{
  "date": "2026-11-23",
  "isCredit": true,
  "customerId": "…guid…",           // o null; o en su lugar:
  "newCustomer": { "name": "Rosa Mora", "phone": "8888-1234" },
  "paidNow": 2000,                   // solo fiado; menor que el total; 0 = nada
  "items": [ { "cartonType": "A", "quantity": 2, "unitPrice": 2500 },
             { "cartonType": "B", "quantity": 1, "unitPrice": 4800 } ]
}

Abonos

MétodoRutaQué haceRespuestas
POST/customers/{customerId}/paymentsAbono suelto. Cuerpo: { date, amount, note }.201, 400, 404
POST/sales/{saleId}/paymentsAbono desde "Abonar": hoy, hacia esa venta. Cuerpo: { amount }.201, 400, 404, 409
GET/sales/{saleId}/paymentsLa venta, cuánto se le ha pagado (paid) y qué parte de qué abono la pagó, más nuevos primero.200, 404
GET/payments?from=&to=Abonos del período y su total. Incluye forSaleDate para "Abono a la venta del…".200, 400
GET/payments/{id}Un abono.200, 404
PUT/payments/{id}Cambia fecha, monto y nota (nunca el cliente).200, 400, 404, 409
DELETE/payments/{id}Borra un abono (el cliente vuelve a deber eso).204, 404, 409

409 en PUT/DELETE: el abono se pagó al hacer un fiado (se cambia desde la venta) o es de un cliente borrado.
