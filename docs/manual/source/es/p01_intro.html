Capítulo 1Introducción

Qué es Eggs App

Eggs App es una aplicación de escritorio para Windows que lleva las cuentas de un negocio pequeño de venta de huevos. La usa una sola persona, mayor y sin experiencia técnica, en su propia computadora. Con ella se anotan:

  • Ventas al contado: el cliente paga en el momento.
  • Ventas fiadas (fiados): el cliente se lleva los huevos y paga después.
  • Abonos: pagos que hace un cliente para ir bajando lo que debe.
  • Gastos: lo que se gasta en el negocio (alimento, vitaminas, cartones…).
  • Resúmenes: cuánto entró, cuánto se gastó y cuánto quedó en un día, una semana o un mes.

Todo el dinero está en colones costarricenses (₡), siempre en números enteros (no hay céntimos).

Tres decisiones que explican casi todo el código

1. No hay internet ni nube

Todo corre en la misma computadora: la pantalla, el "servidor" y la base de datos. No hay cuentas de usuario ni contraseñas. Los datos viven en un archivo (eggs.db) dentro de la carpeta del usuario de Windows.

2. El usuario es una persona mayor

Por eso los botones son grandes (56 píxeles), el texto nunca baja de 18 píxeles, hay pocas acciones por pantalla, todo lo importante pide confirmación y los mensajes están en español sencillo, diciendo qué hacer ("Por favor llame a Billy").

3. Los datos no se pueden perder ni descuadrar

Nada se borra de verdad (se marca como borrado), los totales y saldos se calculan siempre desde los registros (nunca se guardan aparte), hay respaldos automáticos todos los días y el servidor rechaza cualquier cambio que dejaría a un cliente debiendo menos de cero.

Capítulo 2Conceptos básicos para empezar

Este capítulo explica, sin dar nada por sabido, las piezas con que está hecha la aplicación. Si ya programa, puede saltárselo.

Las tres partes de una aplicación como esta

Frontend (la interfaz)

Lo que la persona ve y toca: botones, tablas, formularios. Aquí está hecho con React, una librería de JavaScript para construir pantallas, escrita en TypeScript (JavaScript con tipos).

Backend (el servidor o API)

El programa que recibe pedidos de la interfaz ("guardá esta venta", "dame las ventas de hoy"), revisa las reglas y habla con la base de datos. Aquí está hecho con ASP.NET Core en C#.

Base de datos

Donde se guardan los datos de forma permanente, en tablas (como hojas de cálculo). Aquí es SQLite: una base de datos completa dentro de un solo archivo.

Lo especial de Eggs App es que las tres partes corren en la misma computadora y en el mismo programa. Un cuarto componente, la "cáscara" de escritorio hecha con WPF, abre la ventana de Windows y muestra la interfaz dentro de ella con WebView2 (el motor del navegador Microsoft Edge, incrustado).

Cómo se hablan: HTTP, API y JSON

La interfaz y el servidor se comunican igual que un navegador con una página web: con pedidos HTTP. Cada pedido tiene un método que dice qué se quiere hacer y una ruta que dice sobre qué:

MétodoPara quéEjemplo en Eggs App
GETLeer algoGET /api/sales?from=2026-11-01&to=2026-11-07 → las ventas de esa semana
POSTCrear algoPOST /api/sales → guarda una venta nueva
PUTReemplazar / editarPUT /api/sales/{id} → cambia una venta
DELETEBorrarDELETE /api/sales/{id} → borra una venta

El conjunto de todas estas rutas es la API (interfaz de programación). Los datos viajan en formato JSON, que es texto con llaves y comillas, por ejemplo:

{ "date": "2026-11-23", "isCredit": false, "customerId": null,
  "items": [ { "cartonType": "A", "quantity": 3, "unitPrice": 2500 } ] }

El servidor contesta con un código de estado: 200 (bien), 201 (creado), 204 (bien, sin contenido), 400 (los datos tienen errores), 404 (no existe), 409 (se rechazó por una regla del negocio).

TérminoQué es
