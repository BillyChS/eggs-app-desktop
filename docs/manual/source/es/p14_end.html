Capítulo 14Cómo cambiar o agregar algo

Antes de tocar nada

  1. Leer CLAUDE.md: tiene todas las reglas del proyecto, en detalle, y se mantiene al día.
  2. Correr dotnet build, dotnet test, pnpm lint y pnpm test para confirmar que todo empieza en verde.
  3. Crear una rama de git. Nunca trabajar directo en main.

Receta de ejemplo: agregar una nota opcional a las ventas

Es un caso inventado, pero muestra por dónde pasa casi cualquier cambio. Primero el servidor, después la interfaz.

Servidor (orden: Command → Validator → Handler → Entity → Endpoint → Migration)

  1. Command (SaleContracts.cs): agregar string? Note = null a SaleCommand, string? Note a SaleFields y a SaleDetail.
  2. Validator (SaleValidator.cs): recortar espacios, vacío → null, y si pasa del máximo, error en español bajo la llave "note".
  3. Handler (CreateSale.cs, UpdateSale.cs): asignar sale.Note = fields.Note. SaleDetail.From la incluye.
  4. Entity (Sale.cs): public string? Note { get; set; }, una constante NoteMaxLength, y en SaleConfiguration: HasMaxLength.
  5. Endpoint: en este caso no cambia (el endpoint ya pasa el comando completo).
  6. Migración: dotnet ef migrations add AddSaleNote --project src/EggsApp.Api --output-dir Data/Migrations. Revisar el archivo generado. Se aplicará sola al arrancar, con copia previa.
  7. Pruebas: en SaleEndpointsTests.cs, que la nota se guarde, se lea, se pueda borrar y que una muy larga dé 400.

Interfaz (orden: Screen → Service/Hook → State)

  1. Pantalla (SaleForm.tsx): un TextArea con etiqueta "Nota (opcional)"; incluirla en el snapshot (para que cuente como cambio sin guardar), en el orden del teclado y en la Ventana de confirmación.
  2. Servicio (services/sales.ts): agregar note a Sale y SaleInput.
  3. Estado: useState en el formulario, iniciado con la nota de la venta que se edita. Mostrar el error de la API bajo el campo (fieldErrors.note).
  4. Pruebas en saleForm.test.tsx con la API falsa.

Para cerrar

  • Subir <Version> (función nueva → número del medio: 1.3.0 → 1.4.0).
  • Actualizar CLAUDE.md si cambia una regla.
  • Commit con Conventional Commits, por ejemplo feat(sales): add an optional note, con Refs: AB#<id> si hay tarjeta en Azure Boards.
  • Pull request; esperar CI en verde; fusionar; etiqueta v1.4.0 para crear el instalador.

Capítulo 15Solución de problemas

Lo primero siempre: abrir el registro del día, %LocalAppData%\EggsApp\logs\eggsapp-AAAA-MM-DD.log. Los mensajes de error de la app muestran esa carpeta.

Lo que se veCausa probableQué hacer
"No se pudo abrir Eggs App porque hay un problema con la instalación."Falta wwwroot\index.html (FrontendNotFoundException).Reinstalar con el instalador. En desarrollo: "Falta la interfaz compilada", correr pnpm build.
"No se pudo abrir Eggs App. No se borró ningún dato."La migración falló: base dañada o de una versión más nueva (DatabaseMigrationException).Ver el registro. Si es más nueva, instalar esa versión. Si está dañada, restaurar un respaldo (Capítulo 12).
"…porque falta un programa en la computadora."Falta Microsoft Edge WebView2 Runtime.Instalarlo desde el enlace de Microsoft (con internet).
Windows no deja abrir ni el instalador ni la appSmart App Control activado o en evaluación.Desactivarlo en Seguridad de Windows.
Se queda en "Abriendo…"Arranque lento o bloqueado.Esperar; si no, cerrar y ver el registro. Un candado de migración abandonado se limpia solo al arrancar.
Abrirla otra vez no abre otra ventanaEs lo esperado: SingleInstance trae al frente la que ya está abierta.Buscar la ventana existente.
Barra lateral: "Sin conexión. Cierre y vuelva a abrir Eggs App."La interfaz no logra hablar con la API.Cerrar y volver a abrir. Ver el registro.
Barra lateral: "No se pudo guardar el respaldo…"Falló el último respaldo, o 3 días de uso sin respaldo."Intentar de nuevo". Ver la línea [Backup] del registro (disco lleno, permisos…).
"La copia en OneDrive no se está haciendo."OneDrive cerrado, sin sesión o la carpeta no existe; 7 días de uso sin copia.Abrir OneDrive, iniciar sesión, confirmar la carpeta Respaldos Eggs App.
"La pantalla de Eggs App dejó de responder."El proceso de la página se colgó.Aceptar volver a abrirla. Revisar que lo último esté guardado.
"Algo salió mal en esta pantalla."Un error en una pantalla de React."Volver a Ventas". Si se repite, es un error de código: reproducirlo con pnpm dev.
No deja borrar un clienteTodavía debe (409).Es una regla: primero que quede al día.
No deja editar o borrar un fiadoQuedaría con menos fiado que lo abonado, o el cliente fue borrado (409).El mensaje dice qué abono corregir primero.
No deja editar un abonoSe pagó al hacer un fiado (SaleId).Cambiarlo desde la venta.
Una fecha sale un día antesAlgún código nuevo usó new Date("YYYY-MM-DD") o toISOString().Usar lib/dates.ts.
Después de actualizar se ve la interfaz viejaNo debería pasar (index.html va sin caché).Confirmar la versión en la barra lateral; reinstalar.
