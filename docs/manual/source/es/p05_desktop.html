Capítulo 5La capa de escritorio (EggsApp.Desktop)

Este proyecto es la "cáscara": el ejecutable que abre la persona. Es pequeño (unos 8 archivos), pero decide el orden de arranque, cómo se cierra la app y qué pasa cuando algo falla.

Archivos del proyecto

ArchivoQué hace
App.xaml.csPunto de entrada. Orden de arranque, apagado y manejo de errores fatales.
MainWindow.xaml(.cs)La ventana maximizada con el texto "Abriendo…" y el control WebView2. Configura el navegador y sus reglas de navegación.

El arranque, paso a paso

Detalles que importan:

  • La ventana va primero. Arrancar la API y migrar la base de datos puede tardar segundos; la persona tiene que ver que la app está abriendo.
  • La API arranca en otro hilo (Task.Run(StartHostAsync)) para no congelar la ventana.
  • Si la persona cierra la ventana mientras arranca, no se le muestra nada (no hay a quién), solo se registra.
  • El idioma del navegador se fija en es-CR (CoreWebView2EnvironmentOptions.Language) para que el calendario de las fechas salga en español aunque Windows esté en inglés.

Solo muestra la appOnNavigationStarting cancela cualquier navegación a una dirección que no sea la de la API (IsAppUrl). Un enlace perdido nunca convierte la ventana en un navegador.

Si el motor del navegador se caeOnProcessFailed: si se cayó el proceso principal, cierra con mensaje; si solo se colgó la página, ofrece volver a abrirla.
Si Windows se está apagandoOnSessionEnding llama a CloseWithoutAsking(): no se pregunta nada, porque detendría el apagado.

Una sola copia (SingleInstance)

Al arrancar, la app intenta crear el mutex Local\EggsApp.Desktop.SingleInstance. Si ya existe, hay otra copia abierta: esta segunda copia activa un evento de Windows (Local\EggsApp.Desktop.Activate) y se cierra. La primera copia está escuchando ese evento (ListenForActivation) y llama a BringToFront(), que restaura y levanta la ventana.

Este nombre está en dos lugares

El instalador (EggsApp.iss, AppMutex=…) usa el mismo nombre del mutex para pedir que se cierre la app antes de instalar. Si se cambia en un lado, hay que cambiarlo en el otro.

El cierre

  1. La persona cierra la ventana (o Windows se apaga).
  2. OnExit llama a StopHost(), que en otro hilo espera hasta 10 segundos a que la API se detenga.
  3. EmbeddedApiHost.DisposeAsync(): deja de recibir pedidos, hace el respaldo del cierre (reemplaza el de hoy con el estado final del día), libera la app y cierra todas las conexiones de SQLite (ClearAllPools), lo que pasa todo del archivo eggs.db-wal al eggs.db.
  4. Si todo salió bien, registra "Closed cleanly." y suelta el mutex.

Dónde están los archivos de la interfaz (AppPaths)

Una app publicada tiene wwwroot\index.html al lado del .exe. En modo Debug (desarrollo) no existe, así que AppPaths.WebRoot usa un atributo DevWebRoot que el .csproj graba solo en Debug y que apunta a src/EggsApp.Api/wwwroot. Por eso, para correr la app de escritorio en desarrollo, primero hay que ejecutar pnpm build.
