Chapter 1Introduction

What Eggs App is

Eggs App is a Windows desktop application that keeps the books of a small egg-selling business. It is used by a single person, elderly and non-technical, on their own computer. With it they record:

  • Cash sales ("al contado"): the customer pays on the spot.
  • Credit sales ("fiados"): the customer takes the eggs and pays later.
  • Partial payments ("abonos"): payments a customer makes to lower what they owe.
  • Expenses ("gastos"): what the business spends (feed, vitamins, cartons…).
  • Summaries ("resúmenes"): how much came in, how much was spent and how much was left over in a day, a week or a month.

All money is in Costa Rican colones (₡), always whole numbers (there are no cents).

Three decisions that explain almost all of the code

1. No internet and no cloud

Everything runs on the same computer: the screens, the "server" and the database. There are no user accounts and no passwords. The data lives in one file (eggs.db) inside the Windows user's folder.

2. The user is an elderly person

That is why the buttons are large (56 pixels), text is never smaller than 18 pixels, each screen has few actions, everything important asks for confirmation, and messages are in plain Spanish that say what to do ("Por favor llame a Billy" — "Please call Billy").

3. Data must never be lost or go out of balance

Nothing is ever really deleted (it is marked as deleted), totals and balances are always calculated from the records (never stored separately), there are automatic backups every day, and the server refuses any change that would leave a customer owing less than zero.

Chapter 2Basic concepts to get started

This chapter explains, assuming nothing, the pieces the application is built from. If you already program, you can skip it.

The three parts of an application like this

Frontend (the user interface)

What the person sees and touches: buttons, tables, forms. Here it is built with React, a JavaScript library for building screens, written in TypeScript (JavaScript with types).

Backend (the server or API)

The program that receives requests from the interface ("save this sale", "give me today's sales"), checks the rules and talks to the database. Here it is built with ASP.NET Core in C#.

Database

Where data is stored permanently, in tables (like spreadsheets). Here it is SQLite: a complete database inside a single file.

What is special about Eggs App is that all three parts run on the same computer and in the same program. A fourth component, the desktop "shell" built with WPF, opens the Windows window and shows the interface inside it with WebView2 (the Microsoft Edge browser engine, embedded).

How they talk: HTTP, API and JSON

The interface and the server communicate the same way a browser talks to a website: with HTTP requests. Each request has a method that says what to do and a path that says what to do it to:

MethodUsed toExample in Eggs App
GETRead somethingGET /api/sales?from=2026-11-01&to=2026-11-07 → that week's sales
POSTCreate somethingPOST /api/sales → saves a new sale
PUTReplace / editPUT /api/sales/{id} → changes a sale
DELETEDeleteDELETE /api/sales/{id} → deletes a sale

The set of all these paths is the API (application programming interface). Data travels as JSON, which is text with braces and quotes, for example:

{ "date": "2026-11-23", "isCredit": false, "customerId": null,
  "items": [ { "cartonType": "A", "quantity": 3, "unitPrice": 2500 } ] }

The server answers with a status code: 200 (OK), 201 (created), 204 (OK, no content), 400 (the data has errors), 404 (doesn't exist), 409 (refused by a business rule).
