Chapter 3Overall architecture

The big picture

When someone opens "Eggs App" from the desktop, Windows starts a single program: EggsApp.Desktop.exe. Inside that program three things live at the same time:

  1. The Windows window (project EggsApp.Desktop, built with WPF). A maximized window with a WebView2 control inside, which works like a browser with no toolbars.
  2. The API (project EggsApp.Api, built with ASP.NET Core). It starts inside the same process, listening only on 127.0.0.1 (the computer itself, unreachable from the network) on a port Windows picks each time. It serves two things: the /api/… routes and the interface files.
  3. The React interface (folder src/web). It is compiled into static files stored in wwwroot. WebView2 requests them from the API and displays them.

Data is stored in %LocalAppData%\EggsApp\eggs.db, a SQLite file. On a typical PC that is C:\Users\<user>\AppData\Local\EggsApp\eggs.db.

Why it is built this way

DecisionReason
A web interface inside a window, instead of a pure WPF windowReact makes it much easier to build accessible, large, good-looking screens, and they can be tested automatically. WebView2 ships with Windows 11.
An HTTP API even though everything is on the same PCIt cleanly separates the interface from the business rules. The same API can run on its own for development, with Swagger, and could serve a mobile version in the future.
The API inside the same process (not a separate service)One program to open and close. No Windows services, and no fixed ports that could clash with another program.
Port chosen by the OS (port 0)It never clashes with another program. Consequence: the page's address changes on every launch, which is why the interface never uses localStorage, cookies or IndexedDB: they would be empty every time.
SQLite in a local fileNo database engine to install, no cost, fast for a family's data volume, and easy to back up by copying one file.
Only one copy of the program at a timeIf it were opened twice there would be two APIs writing to the same file. A second attempt to open it just brings the open window to the front (SingleInstance).
Listens only on 127.0.0.1 and checks the Host headerNo other computer can connect, and a malicious website cannot trick the browser into reaching the API (protection against "DNS rebinding").

The layers, from top to bottom

Golden rule: business rules live on the server

The interface checks many things to help the user (for example, that the price isn't empty), but the server checks everything again and is the only one that decides. For example, a sale's total is always calculated by the server, which ignores any total it is sent. If the interface and the API ever disagree, the API wins.

<Nullable>enable</Nullable>                     the compiler warns when something can be null
<ImplicitUsings>enable</ImplicitUsings>           common usings already included
<TreatWarningsAsErrors>true</TreatWarningsAsErrors> a warning breaks the build!
<Version>1.3.0</Version>                         the ONLY place the version is set

Since warnings are errors, the code must build clean. If a warning appears, fix its cause; don't suppress it.
