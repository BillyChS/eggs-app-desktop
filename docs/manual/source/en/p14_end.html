Chapter 14How to change or add something

Before touching anything

  1. Read CLAUDE.md: it has all the project's rules, in detail, and it is kept up to date.
  2. Run dotnet build, dotnet test, pnpm lint and pnpm test to confirm everything starts green.
  3. Create a git branch. Never work directly on main.

Example recipe: adding an optional note to sales

It's a made-up case, but it shows where almost any change goes. Server first, then the interface.

Server (order: Command → Validator → Handler → Entity → Endpoint → Migration)

  1. Command (SaleContracts.cs): add string? Note = null to SaleCommand, and string? Note to SaleFields and SaleDetail.
  2. Validator (SaleValidator.cs): trim it, empty → null, and if it's over the maximum, a Spanish error under the "note" key.
  3. Handler (CreateSale.cs, UpdateSale.cs): assign sale.Note = fields.Note. SaleDetail.From includes it.
  4. Entity (Sale.cs): public string? Note { get; set; }, a NoteMaxLength constant, and in SaleConfiguration: HasMaxLength.
  5. Endpoint: no change in this case (it already passes the whole command).
  6. Migration: dotnet ef migrations add AddSaleNote --project src/EggsApp.Api --output-dir Data/Migrations. Review the generated file. It applies itself at startup, with a copy first.
  7. Tests: in SaleEndpointsTests.cs, that the note is saved, read, can be cleared, and that a very long one gives 400.

Interface (order: Screen → Service/Hook → State)

  1. Screen (SaleForm.tsx): a TextArea labeled "Nota (opcional)"; include it in the snapshot (so it counts as an unsaved change), in the keyboard order and in the confirmation window.
  2. Service (services/sales.ts): add note to Sale and SaleInput.
  3. State: a useState in the form, initialized with the note of the sale being edited. Show the API's error under the field (fieldErrors.note).
  4. Tests in saleForm.test.tsx with the fake API.

To finish

  • Bump <Version> (new feature → middle number: 1.3.0 → 1.4.0).
  • Update CLAUDE.md if a rule changes.
  • Commit with Conventional Commits, for example feat(sales): add an optional note, with Refs: AB#<id> if there's an Azure Boards item.
  • Pull request; wait for green CI; merge; tag v1.4.0 to build the installer.

Rules checklist

✓Rule
☐Text the user sees in Spanish; code, comments, commits and docs in English.
☐Zero warnings when building.
☐Money as long (never decimal). Guid keys generated in code. Every entity inherits BaseEntity.
☐Dates: DateTime.Now on the server; local YYYY-MM-DD in the interface, never toISOString(), never new Date("YYYY-MM-DD"). Use lib/dates.ts and lib/money.ts.
☐No ExecuteUpdate/ExecuteDelete on entities. When deleting, load the related rows that must be deleted too.
☐Balance rules filter on IsCredit, not on CustomerId alone. Balances and totals are never stored: they are calculated.
☐Compare names with CustomerNames in C#, not in SQL.
☐New endpoints go inside the /api group of UseEggsApp().
☐No localStorage, sessionStorage, IndexedDB or cookies. What must last goes through the API to SQLite; screen state goes in the address.
☐56 px controls, 18 px+ text, at most 2–3 main actions per screen, confirm before deleting. Choices among a few options use Dropdown, never <select>.
☐Forms: useUnsavedChanges, useOneAtATime, no <form>; Enter moves on and never saves; the save button always in sight at 1920×1080 and 1366×768.
☐Multi-step popups: each step in the same Modal, never one dialog on top of another.
☐Navigation: "‹ Volver" always goes to the parent page, never browser history.
☐User data only under %LocalAppData%\EggsApp. A backup never throws into the host. Never commit .db files.
☐Installer: never touch %LocalAppData%\EggsApp; keep AppId and AppMutex.

Chapter 15Troubleshooting

Always first: open the day's log, %LocalAppData%\EggsApp\logs\eggsapp-YYYY-MM-DD.log. The app's error messages show that folder.

What you seeLikely causeWhat to do
"No se pudo abrir Eggs App porque hay un problema con la instalación." (installation problem)wwwroot\index.html is missing (FrontendNotFoundException).Reinstall with the installer. In development: "Falta la interfaz compilada", run pnpm build.
"No se pudo abrir Eggs App. No se borró ningún dato." (couldn't open; no data deleted)The migration failed: the database is damaged or from a newer version (DatabaseMigrationException).Check the log. If it's newer, install that version. If it's damaged, restore a backup (Chapter 12).
"…porque falta un programa en la computadora." (a program is missing)Microsoft Edge WebView2 Runtime is missing.Install it from Microsoft's link (needs internet).
Windows won't open the installer or the appSmart App Control is On or in Evaluation.Turn it off in Windows Security.
Stuck on "Abriendo…"Slow or blocked startup.Wait; otherwise close it and check the log. An abandoned migration lock is cleared automatically at startup.
Opening it again doesn't open a new windowExpected: SingleInstance brings the open one forward.Find the existing window.
Sidebar: "Sin conexión. Cierre y vuelva a abrir Eggs App."The interface can't reach the API.Close and reopen. Check the log.
Sidebar: "No se pudo guardar el respaldo…"The last backup failed, or 3 days of use with no backup."Intentar de nuevo". Look at the [Backup] line in the log (disk full, permissions…).
"La copia en OneDrive no se está haciendo."OneDrive closed, signed out, or the folder doesn't exist; 7 days of use with no copy.Open OneDrive, sign in, confirm the Respaldos Eggs App folder.
"La pantalla de Eggs App dejó de responder." (the screen stopped responding)The page's process hung.Accept reopening it. Check the last entry was saved.
"Algo salió mal en esta pantalla."An error in a React screen."Volver a Ventas". If it repeats, it's a code bug: reproduce it with pnpm dev.
Won't let you delete a customerThey still owe money (409).It's a rule: they must be up to date first.
Won't let you edit or delete a credit saleCredit would fall below what was paid, or the customer was deleted (409).The message says which payment to fix first.
Won't let you edit a paymentIt was paid when a credit sale was made (SaleId).Change it from the sale.
A date shows one day earlierSome new code used new Date("YYYY-MM-DD") or toISOString().Use lib/dates.ts.
After updating, the old interface showsShouldn't happen (index.html is served with no-cache).Confirm the version in the sidebar; reinstall.
