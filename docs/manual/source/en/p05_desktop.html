Chapter 5The desktop layer (EggsApp.Desktop)

This project is the "shell": the executable the person opens. It is small (about 8 files), but it decides the startup order, how the app closes and what happens when something fails.

Startup, step by step

Details that matter:

  • The window comes first. Starting the API and migrating the database can take seconds; the person must see that the app is opening.
  • The API starts on another thread (Task.Run(StartHostAsync)) so the window doesn't freeze.
  • If the person closes the window during startup, nothing is shown (there's nobody to tell); it is only logged.
  • The browser language is fixed to es-CR (CoreWebView2EnvironmentOptions.Language) so the date picker's calendar is in Spanish even if Windows is in English.

The browser rules (MainWindow)

WhatHow and why
Only shows the appOnNavigationStarting cancels any navigation to an address that isn't the API's (IsAppUrl). A stray link never turns the window into a browser.
No new windowsOnNewWindowRequested blocks them.
No "browser feel" (Release only)The right-click menu, dev tools, browser shortcuts, zoom, status bar, autofill and password saving are turned off. Debug keeps them for debugging.
Warn before closing with unsaved changesThe page sends the window the message "unsaved-changes" or "no-unsaved-changes" (see services/desktopShell.ts). If there are changes, pressing the X asks "Tiene cambios sin guardar. ¿Cerrar Eggs App sin guardar?" ("You have unsaved changes. Close without saving?"), with "No" as the safe choice.
If the browser engine crashesOnProcessFailed: if the main process died, it closes with a message; if only the page hung, it offers to reopen it.
If Windows is shutting downOnSessionEnding calls CloseWithoutAsking(): nothing is asked, because it would hold up the shutdown.

One copy at a time (SingleInstance)

At startup the app tries to create the mutex Local\EggsApp.Desktop.SingleInstance. If it already exists, another copy is open: this second copy signals a Windows event (Local\EggsApp.Desktop.Activate) and exits. The first copy is listening for that event (ListenForActivation) and calls BringToFront(), which restores and raises the window.

This name lives in two places

The installer (EggsApp.iss, AppMutex=…) uses the same mutex name to ask for the app to be closed before installing. If it changes in one place, it must change in the other.

Shutdown

  1. The person closes the window (or Windows shuts down).
  2. OnExit calls StopHost(), which waits on another thread for up to 10 seconds for the API to stop.
  3. EmbeddedApiHost.DisposeAsync(): stops taking requests, makes the closing backup (replacing today's with the day's final state), disposes the app and closes every SQLite connection (ClearAllPools), which moves everything from eggs.db-wal into eggs.db.
  4. If all went well, it logs "Closed cleanly." and releases the mutex.

Where the interface files are (AppPaths)

A published app has wwwroot\index.html next to the .exe. In Debug (development) it doesn't, so AppPaths.WebRoot uses a DevWebRoot attribute that the .csproj writes only in Debug, pointing to src/EggsApp.Api/wwwroot. That's why, to run the desktop app in development, you must run pnpm build first.
