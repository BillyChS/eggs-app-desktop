Chapter 12Backups, logs and restoring

Where the application writes

Everything goes under %LocalAppData%\EggsApp (AppDataPaths), never next to the program:

PathContents
eggs.dbThe data. While the app is open, eggs.db-wal and eggs.db-shm exist too.
eggs.dev.dbDevelopment data (standalone API and dotnet ef).
backups\daily\Automatic backups, one per day: eggs-YYYY-MM-DD.db.
backups\Copies made before each migration (eggs-YYYY-MM-DD_HH-mm-ss-fff.db, the 5 newest) and backup-state.json.
settings.jsonOptional, written by hand: the backups' second location.
WebView2\The embedded browser's internal data.
logs\eggsapp-YYYY-MM-DD.log, one per day, kept 7 days.

The one exception is the backups' second copy: by default %OneDrive%\Respaldos Eggs App.

How backups work

  • Who: BackupWorker (a background task: checks at startup and every hour) and EmbeddedApiHost.DisposeAsync (on close). Desktop app only: Backup:Enabled is set only by EmbeddedApiHost, so the standalone API and the tests never back up.
  • Why the file isn't simply copied: part of what was saved can still be in eggs.db-wal. SQLite's backup API copies the complete state.
  • One backup at a time (SemaphoreSlim). Nothing in DatabaseBackups throws errors outward.
  • Pruning only deletes files whose names match the BackupFiles patterns exactly, so it can never delete other files in the OneDrive folder. It also deletes abandoned .partial files older than one day.
  • Backups are counted, not calendar days: if the app isn't used for weeks, the old backups aren't lost.

When the sidebar warns

Normally it says "Último respaldo: hoy 8:15 a. m." (last backup: today 8:15 a.m.). It warns ("No se pudo guardar el respaldo… Por favor llame a Billy.", with the "Intentar de nuevo" button) only if:

  • the last attempt failed (remembered across restarts in backup-state.json), or
  • the app was used on 3 days with no good backup since (days of use, not calendar days: a long weekend never causes a warning).

For the second copy the threshold is 7 days of use ("La copia en OneDrive no se está haciendo." — the OneDrive copy isn't being made). A skipped copy counts as a day without a copy, not as a failure.

Setting up the second location

// %LocalAppData%\EggsApp\settings.json
{ "Backup": { "SecondFolder": "E:\\Respaldos Eggs App" } }    // another folder, e.g. a USB drive
{ "Backup": { "SecondFolder": "off" } }                       // no second copy

Without settings.json, if OneDrive is set up in Windows (the OneDrive environment variable), %OneDrive%\Respaldos Eggs App is used. The app only sees the local folder: check now and then at onedrive.live.com that it has recent files.

The failure log

FailureLog writes to logs\eggsapp-YYYY-MM-DD.log:

  • one line at startup: [Desktop] Started. Version 1.3.0+…, port 51234.
  • the migrations applied and the path of the copy made before them;
  • every backup: where, size, what was pruned, how the second copy went;
  • every error: from the window, from API requests (Error or Critical level), uncaught exceptions;
  • one line on a clean close: [Desktop] Closed cleanly.

Limits: 7 days of files and 5 MB per file (if something fails in a loop, the rest of that day is dropped). Writing the log never throws. The window's error messages show this folder's path.

Restoring a backup

This is done by Billy, not by the person who uses the app. Nothing is deleted until the end.
  1. Close Eggs App. In Task Manager, confirm no EggsApp.Desktop process is left.
  2. Choose the backup. The newest is in backups\daily, with the date in the name. If the disk died, take one from Respaldos Eggs App in OneDrive (download it first). To go back to the state before a migration, use one of backups\eggs-…_HH-mm-ss-fff.db.
  3. Move the current database aside. In %LocalAppData%\EggsApp, create a folder like before-restore-2026-11-23 and move eggs.db into it, together with eggs.db-wal and eggs.db-shm if they exist. A leftover -wal next to the restored file would be applied to it and corrupt it.
  4. Put the backup in place. Copy (don't move) the chosen backup into %LocalAppData%\EggsApp and rename the copy to eggs.db.
  5. Open Eggs App and check the latest sales, payments and expenses. A backup from an older version is migrated at startup (with a copy first). One from a newer version is refused without changing anything.
  6. If everything is right, delete the before-restore-… folder. If not, close the app and put those files back.
