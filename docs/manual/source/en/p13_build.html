Day-to-day commands

dotnet build                                 # builds everything; must give ZERO warnings
dotnet test                                  # server tests
dotnet run --project src/EggsApp.Api         # standalone API: http://localhost:5080/swagger
dotnet run --project src/EggsApp.Desktop     # the desktop app (run pnpm build first)

cd src/web
pnpm install                                 # once, or when package.json changes
pnpm dev                                     # interface with hot reload (and /dev/componentes)
pnpm build                                   # builds the interface into src/EggsApp.Api/wwwroot
pnpm lint                                    # checks the style
pnpm test                                    # interface tests
The most convenient way to work on the interface

Run the standalone API (dotnet run --project src/EggsApp.Api) and, in another terminal, pnpm dev, then open the address Vite prints. Changes show on save, without building. You work on eggs.dev.db, never on the real data.

Notes: dotnet build and dotnet test never run pnpm and don't need the interface built. The API only picks up wwwroot if it exists at startup, so restart it after the first pnpm build.

The automated tests

Server (tests/EggsApp.Tests, xUnit)

They are integration tests: EggsAppFactory (a WebApplicationFactory<Program>) starts the real API pointed at a database in a temporary folder (TestDatabaseFolder), makes real HTTP requests and checks the responses and what was stored (it can open the database directly with ConnectToDatabase()).

They must turn the backups' second location off or point it at a temporary folder; otherwise they would write into the real OneDrive.

Interface (Vitest)

The *.test.ts(x) files sit next to the code they test. test/api.tsx replaces fetch with a fake API (fakeApi()): each test says what each route answers and then checks which requests were made. Screens are rendered with the real router in memory. test/setup.ts fails the test if any screen crashes during it. The time zone is fixed to America/Costa_Rica so that date bugs also show up on machines set to UTC.

Continuous integration (GitHub Actions)

  • Each pull request detects which parts changed and runs Backend CI (Windows: restore, build with -warnaserror, test) and/or Frontend CI (Ubuntu: pnpm install, lint, build). The ci-gate job summarizes the result and is the only required check on main.
  • Pushes to main run both. CodeQL checks security. Dependabot proposes weekly updates.
  • installer.yml builds the installer when a v* tag is pushed and creates a GitHub Release with the installer and its SHA-256. It fails if the tag doesn't match <Version>.

The version

It is set only in <Version> in Directory.Build.props. It shows at the bottom left of the sidebar ("Versión 1.3.0"), in the log's startup line, in GET /api/health, in the installer's name and in Windows' list of programs. It is bumped in the same pull request that changes what ships: the last number for fixes, the middle one for new features, the first one for changes in how the app is used.

Publishing and building the installer

dotnet publish src/EggsApp.Desktop -p:PublishProfile=win-x64       # → src/EggsApp.Desktop/bin/publish/win-x64
powershell -ExecutionPolicy Bypass -File installer\build.ps1      # → artifacts\installer\EggsApp-Setup-1.3.0.exe

What publishing does:

  • It is self-contained: it includes .NET, so the PC only needs the WebView2 runtime (which Windows 11 includes).
  • Frontend.targets runs pnpm install --frozen-lockfile and pnpm build and copies wwwroot into the output. With -p:SkipFrontendBuild=true the existing wwwroot is used.
  • Files the app never uses are removed: EggsApp.Api.exe and its runtimeconfig (the API only runs in-process), appsettings.Development.json and the documentation .xml files. The .pdb files stay so errors in the log have line numbers.

build.ps1 also checks that the essential files are there (EggsApp.Desktop.exe, EggsApp.Api.dll, appsettings.json, e_sqlite3.dll, wwwroot\index.html), that none of the removed ones nor any .db slipped in, and at the end prints the size (about 55 MB) and the SHA-256.

Installing and updating on the PC

Before the first install

  1. Smart App Control (Windows Security → App & browser control) must be Off: if it's On or in Evaluation, it blocks unsigned apps like this one with no way to open them.
  2. OneDrive: sign in with the backups' account and leave it starting with Windows.
  3. If a version was ever copied by hand, delete that folder and its shortcuts. Never delete %LocalAppData%\EggsApp: it's the data.

Installing or updating

  1. Copy EggsApp-Setup-<version>.exe (USB or from the GitHub Release). Optional: compare Get-FileHash with the SHA-256.
  2. Run it. SmartScreen says "Windows protected your PC": More info → Run anyway.
  3. If it's an update and the app is open, the installer asks to close it and waits.
  4. Install → Finish with "Abrir Eggs App" checked. Data, backups and settings.json stay as they are. If the version changes the database, the app copies it to backups\ before migrating.

What to check afterwards

  • The bottom left says Versión X.Y.Z.
  • The latest sales, payments and expenses are there.
  • The sidebar says "Último respaldo: hoy …" with no warning.
  • The day's log has Started. Version X.Y.Z+… (and, if the database changed, Applied migrations: …).

Uninstalling or going back to an older version

Settings → Apps → Eggs App → Uninstall removes only the program; the data stays and reappears after reinstalling. To go back: uninstall and install the older version. If the newer one had changed the database, the older one refuses to open it ("No se pudo abrir Eggs App. No se borró ningún dato."); then reinstall the newer one, or restore the pre-migration copy (losing what was entered since).
