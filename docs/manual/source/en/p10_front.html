Chapter 10The user interface (src/web)

How the interface starts

index.html has an empty <div id="root">. main.tsx creates the router with the routes from routes.tsx and renders it there:

const router = createBrowserRouter(routes)
createRoot(document.getElementById('root')!).render(<StrictMode><RouterProvider router={router} /></StrictMode>)

Every route sits inside AppLayout, which puts the sidebar (Sidebar) on the left and the current screen on the right, and wraps everything in MessagesProvider (success and error messages). If a screen crashes, ErrorScreen is shown ("Algo salió mal en esta pantalla." — something went wrong on this screen) with a button that reloads everything on Ventas.

Talking to the API: http.ts

Every call goes through request<T>(path, { method, body, signal }):

  • It uses fetch with a relative path (/api/…): since the interface is served by the same API, the port doesn't need to be known.
  • It cancels the request after 10 seconds, and also if the screen no longer wants the answer (signal).
  • If the response isn't OK, it throws an ApiError with status, fieldErrors (the first message of each field of a 400) and refusal (the message of a 409).
  • A 204 returns undefined; anything else is read as JSON.

In development, Vite forwards /api to http://localhost:5080 (vite.config.ts). That number must match launchSettings.json.

The hooks every screen uses

HookWhat for
useLoad(key, load, goneMessage)Loads what a screen shows, once per key. Drops answers that arrive late. Returns loading, ready, failed (to offer "Intentar de nuevo") or gone (a 404: shows the message and the screen leaves).
useSalesPage, useExpenseList, useCustomerListThe same for lists. Ventas requests sales, payments and the summary in parallel (so the cards match Resúmenes). The customer list waits 300 ms after typing stops.
useOneAtATime()Ignores a second click while the first is working, and with finish() blocks everything once saved. The button is not disabled, because that would take away keyboard focus.
useUnsavedChanges(hasChanges)If there are unsaved changes, asks before going to another screen (with React Router's useBlocker) and tells the Windows window, which asks before closing.
useServerStatus()Checks /api/health every 30 s: "Conectado" (connected) or "Sin conexión. Cierre y vuelva a abrir Eggs App." (no connection, close and reopen), and the version.
useBackupStatus()Checks the backup status as often, and retry() for "Intentar de nuevo".

Base components and why they exist

ComponentImportant detail
ButtonAlways a real <button> (Enter, Space and focus just work). Navigation uses buttons too: links ignore the Space key. Variants: primary, secondary, danger, dangerOutline, success.
FieldThe base of every input: an always-visible label, a hint underneath, and the error in words with an icon, not just in color.
MoneyInputA text field (not type="number", which accepts "e" and changes with the mouse wheel). Adds thousands dots while typing, keeps the caret in place, puts the ₡ inside the field, and refuses cents ("12500,50" gives an error instead of becoming ₡1,250,050).
DateInput / DayPickerThe browser's date field (its value is already local YYYY-MM-DD), plus large "Hoy" (today) and "Ayer" (yesterday) buttons, because the browser's calendar is small and CSS can't reach it.
DropdownA hand-built dropdown, because a <select>'s list is drawn tiny by the browser. Keyboard works like a select. Used for "¿Cómo pagó?" (how did they pay?), "Tipo de cartón", "¿Qué tipo de gasto?".
ModalA native <dialog>: the browser keeps Tab inside it and blocks what's behind. A click outside doesn't close it. Ignores a held-down Enter. Multi-step popups show each step in the same Modal, never a second dialog on top.
ConfirmDialog"¿Está seguro?" (are you sure?) with focus on the safe choice, so a stray Enter never confirms.
ConfirmationWindowThe "Ventana de confirmación": summarizes what is about to be saved, with focus on "Editar"; only "Listo" (done) saves. If it fails, the error stays inside it.
MessagesProvidershowSuccess and showError: a Modal that stays until "Aceptar" (OK) is pressed.

Dates and money in JavaScript

Two traps the code avoids on purpose
  • new Date("2026-11-04") means midnight UTC, which in Costa Rica is November 3. lib/dates.ts builds dates from their parts. And toISOString() is never used to send a date: at 6 p.m. it would already be tomorrow. todayLocal() is used instead.
  • Intl doesn't produce "₡12.500" for es-CR (it gives "12 500"). lib/money.ts (formatColones, parseColones) does it by hand. Short weekday and month names are hand-made too ("set" for September, as it's said in Costa Rica).

The period lives in the address

Ventas and Gastos use PeriodBar: Hoy (today), Ayer (yesterday), Otro día (another day), Esta semana (this week, Monday to Sunday) or Este mes (this month), with ‹ › arrows for weeks and months that never go past the current one. The period is kept in the address (periodView.ts): ?fecha=2026-11-07, ?semana=2026-11-02 (its Monday) or ?mes=2026-11; Ventas adds &pestana=fiado|abonos (salesView.ts). Resúmenes uses ?periodo=semana&desde=…. Because it's in the address:

  • it survives a reload (browser storage isn't used, since it's empty on every launch);
  • screens opened from there carry it, and after saving they return to that week or month if the date fits, or to that day if not;
  • changing the period replaces the address, so the history doesn't fill up.

The screens, one by one

Ventas — Sales (SalesScreen)

Three cards: "Entró hoy" (came in today: cash + payments, with the breakdown), "Fiado hoy" (on credit today) and "Cartones vendidos" (cartons sold, of 15 and of 30). Their numbers come from GetSummary, so they match Resúmenes. Below: Fiado, Contado (the default) and Abonos tabs, a search by name or phone (accent-insensitive; "88124455" finds "8812-4455") and the table. For a week or month, the table adds a Date column. Each credit sale shows its status ("Debe ₡X", "Pagado con abonos") and an Abonar button (or "Ver abonos" if already paid), which opens AbonoDialog. Deleting asks first, saying what the customer will owe afterwards.

The sale form (SaleForm)

A page with a fixed bar at the bottom (FormFooter: total, Cancelar, Guardar venta, and Borrar venta apart on the left when editing). The keyboard order is fixed; Enter moves on and never saves:

Date → How did they pay? → (per line) Carton type → Quantity → Price
     → Did they pay something now? (credit only) → Customer → Guardar venta

The screen opens with focus on "¿Cómo pagó?". A cash sale starts with "Cliente sin nombre" already chosen (and the Customer step is skipped). If a new customer is chosen and there's a similar one, it asks first. "Guardar venta" doesn't save: it opens the confirmation window (a credit sale with a partial payment appears there as "Mixto"), and only "Listo" saves. If the server rejects a field, "Editar" returns to the form with focus on that field. Each carton type's price starts at the last price used.

Abonar — the pay-toward-a-sale dialog (AbonoDialog)

Shows what the sale owes, the amount (always empty when it opens), what it will owe afterwards, and the payments that have paid it ("₡500 (de un abono de ₡2.000)" when only part of a payment went to that sale). Enter goes to "Guardar abono", which asks "Sí, guardar" / "No" before saving.

Clientes — Customers and statement

CustomersScreen lists customers with their balance ("Debe ₡8.000" or "Al día" — up to date) and the total receivable. CustomerStatementScreen shows the balance, the movements (credit sale +, payment −) with the balance after each, and cash purchases apart. From there you record a standalone payment (PaymentForm), edit the customer, or edit a credit sale (which returns to the statement, ?cliente=).

Gastos — Expenses (ExpensesScreen)

A "Gastado hoy / esta semana…" card, a toolbar with "Buscar gasto" (search by type or note, accent-insensitive), "Filtrar" (a popup with a checkbox per type; the button says "Filtrar (N)") and "Tipos de gasto". Search and filter are applied in the browser and kept when the period changes; the footer says "N de M gastos". "Nuevo gasto" and "Editar" open ExpenseDialog over the page: Date → ¿Qué tipo de gasto? → ¿Qué gasto fue? ("Otro" only) → Amount → Note → Guardar gasto, which shows the confirmation in the same popup. "Tipos de gasto" (ExpenseTypesDialog) lists the types with their count and lets you add and remove them.

Resúmenes — Summaries (SummariesScreen)

Choose Day, Week or Month with arrows. It shows Came in, Spent and Left over in large type (with a real minus sign when negative, and "Se gastó más de lo que entró." — more was spent than came in), the period's credit sales, the total receivable today, spending by type, cartons sold, "Día por día" (day by day; clicking a day switches the summary to that day) and "Mejores clientes" (best customers) with "Ventas sin cliente" right below.
